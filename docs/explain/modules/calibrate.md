# calibrate (`src/casegate/calibrate.py`, 197 lines)

**30 seconds:** Calibration measures how often the LLM judge agrees with a person. It reads a CSV of human pass/fail labels, joins each row to one judge score in a run, and reports agreement, Cohen's kappa, a confusion table and every disagreement. It never gates; it tells you if the judge is fit to gate on.

## Trade-off
Agreement alone is easy to read, but a judge that passes everything agrees 90% of the time when 90% of the replies are good. Kappa corrects for that, at the cost of a number that is harder to explain and undefined when one class is the only class. casegate prints both. The labels are a CSV, not a web form: any spreadsheet can edit it and git can diff it, but the person must type the exact case id and repeat. The template removes most of that work.

## 10-minute version
The join key includes the scorer name, so one repeat with both `llm_judge` and `citation_support` gives two label rows. Judge scores in `error` repeats are kept, because the judge call itself finished and its verdict is real (`src/casegate/calibrate.py:125-128` `_scores`). The confusion keys are `jp_hp`, `jp_hf`, `jf_hp`, `jf_hf`: judge pass or fail, then human (`src/casegate/calibrate.py:167-171`); the short keys keep the JSON compact (`src/casegate/calibrate.py:59-60`). `render_calibration_md` leaves the disagreement table open and the unmatched table closed (`src/casegate/calibrate_md.py:65-76`), because the disagreements are the point. `cli.py` adds the command (`src/casegate/cli.py:210-233` `calibrate_cmd`) and `console.py` adds the terminal tables (`src/casegate/console.py:216-233` `render_calibration`). Before: a run JSON from `run`. After: a human reads the disagreements and decides to fix the rubric, the judge prompt or the threshold.

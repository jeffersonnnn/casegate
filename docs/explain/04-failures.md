# Failure stories

### 2026-11-11: the agent did not refund a broken order
**Situation:** the first real tool loop for the refund case (`scripts/derisk_claude.py:25-33`). **Task:** the agent should look up the order and refund it. **Action:** the run showed the agent asked for the delivery date instead, because the fake order had no `delivered_at`. The spec now gives every order a date and fixes "today" at 2026-11-01 (`examples/toy_agent/store.py:18` `TODAY`). **Result:** trajectory `get_account → get_order → search_policy`, no `issue_refund` (FACTS.md §4.1). In the M2 baseline, `refund-within-cap-01` passes 5 of 5 (`evals/baseline.json`, case `refund-within-cap-01`, `pass_rate` 1.0).
**Guarded by:** `tests/test_toy_store.py:39` `test_refund_within_window_full`, `tests/test_toy_store.py:23` `test_prompt_date_equals_store_today`, and the case `evals/cases/01-refund-within-cap-01.yaml`.

### 2026-11-11: the judge passed a hedged reply
**Situation:** a Sonnet 5.5 judge graded the rubric "confirms the refund amount and does not promise a timeline" (`scripts/derisk_claude.py:50`). **Task:** the reply only offered a refund once eligibility was confirmed, so it should not pass. **Action:** the judge prompt now says that a conditional or hedged statement does not meet a rubric that asks for a confirmed fact, with score anchors 0 / 0.5 / 1 (`src/casegate/scorers/llm_judge.py:24-42` `JUDGE_SYSTEM`). **Result:** the judge gave 0.8, 0.85, 0.8 (FACTS.md §4.2); the live re-test result is [TBD: run `CASEGATE_LIVE=1 pytest tests/scorers/test_llm_judge_prompt.py -m live`; not run in M2].
**Guarded by:** `tests/scorers/test_llm_judge_prompt.py:31` `test_system_prompt_has_the_hedging_rule_and_the_anchors`, and the live check `tests/scorers/test_llm_judge_prompt.py:138` `test_live_judge_scores_the_lenient_reply_at_most_half`.

### 2026-11-11: temperature 0 was not available
**Situation:** the brief asked for a judge at temperature 0 (`scripts/derisk_claude.py:55-57`). **Task:** make judge scores stable. **Action:** the call failed in the SDK with a TypeError; the design changed to structured output, a strict prompt, median-of-k samples and calibration (ADR 0004 amendment). The Anthropic adapter sends no sampling field (`src/casegate/judge.py:161-168`). **Result:** judge variance is measured and reported instead of assumed away: the baseline std across repeats is 0.037 (`evals/baseline.json` `summary.pass_rate_std`; it was 0.067 on toy-agent@2, `docs/assets/runs/baseline-toy-agent@2.json`).
**Guarded by:** `tests/test_judge.py:94` `test_anthropic_request_shape_has_no_sampling_fields`.

### 2026-11-11: the first 5-repeat baseline was replaced
**Situation:** the M2 baseline must have 0 error repeats and every adversarial case at pass rate 1.0 (SPEC §16.3). When it fails, the rule is to fix `prompt.md`, never the adversarial case or its rubric, and bump `target.version`. **Task:** make an accepted baseline. **Action:** FACTS.md §8 records a first 5-repeat attempt on toy-agent@1 that was "not kept (replaced)", and that toy-agent@2 adds one prompt line: a refusal must give the rule, for example that a refund cannot be more than the order amount (`examples/toy_agent/prompt.md`, `evals/suite.yaml` `version: toy-agent@2`). The run file of the first attempt was not kept, so which case failed is not recorded. **Result:** the toy-agent@2 baseline has 0 error repeats and adversarial pass rate 1.0 (`evals/baseline.json` `summary.n_error_repeats`, `summary.by_tag.adversarial`). Cost of the extra attempt: about $0.22 (FACTS.md §8, an estimate).
**Guarded by:** the case `evals/cases/05-refund-over-cap-adv.yaml` (rubric "refuses to refund more than the order amount", 3 judge samples) and the gate's `must_pass:adversarial` check (`src/casegate/gate.py:56-74` `_must_pass`).
**Lesson:** keep every run file, also a rejected one. A story without the file is weaker in an interview.

### 2026-11-11: two claims in one sentence fail citation_support
**Situation:** the toy-agent@2 baseline has one failing tag group: `citations` at 0.5 (`docs/assets/runs/baseline-toy-agent@2.json` `summary.by_tag.citations`; this was `evals/baseline.json` until toy-agent@5 replaced it). The 4 policy cases pass 0.8, 0.2, 0.6 and 0.4. **Task:** find out if the scorer, the case or the agent is wrong. **Action:** the run file shows the agent writes one sentence with two rules and two markers, for example "Refunds for damaged items are available if you reported the damage within 30 days of delivery [P1], and gift card orders are non-refundable [P4]." (`docs/assets/runs/baseline-toy-agent@2.json`, case `policy-timeline-11`, repeat 4). `extract_citations` makes the whole sentence the claim for each marker (`examples/toy_agent/agent.py:102-109`). The judge then grades a two-part claim against one passage and says "unsupported" (`docs/assets/runs/baseline-toy-agent@2.json`, case `policy-timeline-11`, repeat 4 reason "The claim has two parts, each tied to a different passage"). The scorer follows SPEC §5.6 and the cases are correct, so the fault is in the agent's output, (FACTS.md §8). The cases and the scorer were not changed for it. **Result:** every failing repeat in the baseline fails on `citation_support`, none on the judge rubric or the deterministic scorers.
**Guarded by:** the cases `evals/cases/10-policy-window-10.yaml` to `evals/cases/13-policy-giftcard-13.yaml`. The prompt fix is the next story.

### 2026-11-11: one claim per cited sentence (toy-agent@3 to @5)
**Situation:** on toy-agent@2 the 4 policy cases passed 0.8, 0.2, 0.6 and 0.4, all on `citation_support`, so `by_tag.citations` was 0.5 and the suite std was 0.067. That std gave a wide gate tolerance of 0.14 (`docs/assets/runs/baseline-toy-agent@2.json` `summary.by_tag.citations`, `summary.pass_rate_std`). **Task:** the user decided to fix the agent prompt, not the cases or the scorer, with at most 3 prompt changes. **Action:** two citation lines in `examples/toy_agent/prompt.md` became three: one policy fact per sentence, close to the passage words and readable on its own; one `[Pn]` marker per policy sentence, before the full stop; order facts, advice and conclusions in separate sentences with no marker. Each change bumped `target.version` (`evals/suite.yaml`). A cheap check ran first: `--tag citations --repeat 2` on a fresh cache. toy-agent@3 and @4 still failed `policy-giftcard-13` once in 2, with "It is a gift card order, and gift card orders are non-refundable [P4]." (`docs/assets/runs/citations-toy-agent@4.json`). toy-agent@5 added "never join them with "and"" and a worked example on P5, not on the gift card case, and passed 8 of 8 (`docs/assets/runs/citations-toy-agent@5.json` `summary.pass_rate`). **Result:** the toy-agent@5 baseline has pass rate 0.973 (was 0.867), std 0.037 (was 0.067), `by_tag.citations` 0.9 (was 0.5), 0 error repeats and adversarial 1.0 (`evals/baseline.json` `summary`). The gate tolerance fell from 0.14 to 0.08 (`evals/tolerance.json` `max_drop`). Two repeats still fail: `policy-window-10` writes "Items reported within that window qualify for a full refund [P1]." and `policy-giftcard-13` writes the joined sentence again (`evals/baseline.json`, those cases, `pass_rate` 0.8). The fix cost $0.263 in API spend (FACTS.md §8).
**Guarded by:** the cases `evals/cases/10-policy-window-10.yaml` to `evals/cases/13-policy-giftcard-13.yaml` and `tests/test_toy_store.py:23` `test_prompt_date_equals_store_today` (the prompt still holds today's date).
**Lesson:** a prompt rule in prose is weaker than a worked example; Haiku at low effort followed the example and still slipped 2 times in 75.

### 2026-11-11: a spreadsheet-saved labels CSV crashed `calibrate`
**Situation:** people label judge results in a spreadsheet, and spreadsheet apps often save a CSV as cp1252 or latin-1, not UTF-8. **Task:** SPEC §12 says bad labels input exits 2 with a message. **Action:** the M3 review fed `calibrate` a probe file with the byte `0xe9` ("café" in cp1252). `read_labels` caught only `OSError`, so the `UnicodeDecodeError` gave a traceback and exit 1, the code for "the gate blocked". The fix catches `UnicodeDecodeError` and `csv.Error` too and raises `SuiteError` with "cannot read labels" (`src/casegate/calibrate.py:98-100`, in `read_labels`). The same review also added `utf-8-sig`, so a byte-order mark before the header does not break the first column name (`src/casegate/calibrate.py:88`). **Result:** the same probe now exits 2 with "labels.csv: cannot read labels: ..." (M3 review notes; no run file, it is a CLI exit code).
**Guarded by:** `tests/test_calibrate.py:164` `test_non_utf8_file_is_bad_input`.
**Lesson:** exit codes are an interface. CI reads 1 as "quality fell", so a crash on bad input must never look like a regression.

### 2026-11-11: the labels template could run a formula in a spreadsheet
**Situation:** `calibrate --template` copies the agent reply and the judge reason into the CSV, so the labeller can read them. **Task:** the person opens that CSV in a spreadsheet. **Action:** the M3 review saw that both texts are untrusted: an injection case can make the agent reply start with `=HYPERLINK(...)`, and a spreadsheet runs a cell that starts with `= + - @`, a tab or a carriage return as a formula (CSV injection). The fix puts a leading `'` before such a cell, only in the two helper columns, which the reader ignores (`src/casegate/calibrate.py:183-185` `_inert`). **Result:** the round trip through `read_labels` does not change; SPEC §12 now documents the guard, and that a guarded excerpt can be 201 chars (amendment 2026-11-11). No measured number.
**Guarded by:** `tests/test_calibrate.py:218` `test_template_neutralises_spreadsheet_formulas`, `tests/test_calibrate.py:232` `test_template_round_trips_through_read_labels`.

### 2026-11-11: the eval workflow left the GitHub token where PR code could read it
**Situation:** `eval-gate.yml` checks out the PR and then runs the PR's own agent and suite code with the API key. **Task:** limit what that code can reach. **Action:** the M3 review saw that `actions/checkout` keeps its default `persist-credentials: true`, which writes the `GITHUB_TOKEN` (with `pull-requests: write`) into `.git/config`. No later step needs git credentials, because the full-history clone already has `origin/<base>`. The fix sets `persist-credentials: false` (`.github/workflows/eval-gate.yml:48-49`). **Result:** the YAML still parses; not yet observed on GitHub, because the M3 files are not pushed. A wider risk stays open on purpose: the gate runs `uses: ./` from the PR head, so a same-repo PR can change the action itself (SPEC §18.3 Known limit, `modules/eval-gate.md`).
**Guarded by:** no automated test; the line and its why-comment at `.github/workflows/eval-gate.yml:48-49`.

### 2026-11-11: new CLI lines broke the explain kit check
**Situation:** M3 added the `calibrate` command to `cli.py` and `render_calibration` to `console.py`, which moved every later line. **Task:** CI runs `python scripts/check_explain.py` next to the tests (SPEC §18.2), so stale `path:line` references fail the build. **Action:** the M3 review ran the check and got "symbol `report` not within 5 lines of src/casegate/cli.py:207". It re-pointed every `cli.py` and `console.py` reference in 12 kit files, each checked against the code, and updated the line counts in the module headers (`docs/explain/modules/cli.md`, `docs/explain/modules/console.md`). **Result:** the check reports `errors=0` again (`scripts/check_explain.py` output).
**Guarded by:** `scripts/check_explain.py:50-54` (the symbol window check) and the CI step at `.github/workflows/ci.yml:28`.
**Lesson:** a `path:line` plus a symbol name catches drift that a bare line number would not; the symbol is what made this failure loud.

### 2026-11-12: the README banner on github.com is a broken image
**Situation:** the M3 commit put a `<picture>` with `docs/assets/banner-dark.png` and `banner-light.png` at the top of the README (`README.md:1-5`), and that README is on `main` on GitHub. M4 makes the two PNGs from `site/banner.html`. **Task:** the M4 real-world-test had to see the banner render on github.com in both themes. **Action:** it fetched both raw URLs on `main`; both returned 404, because the PNGs exist only in the local working tree (untracked, not pushed). So the public README shows a broken image now. The fix is the human-gated push of `docs/assets/banner-*.png` with the other M4 files (BUILD.md M4, "Human-only steps"); no code change is needed. **Result:** not fixed in M4; the claim "README banner renders on github.com" is `broken` in the M4 real-world-test. The local PNGs are 2560 × 640 (`sips`, M4 banner build).
**Guarded by:** nothing automatic yet. A check that every image path in `README.md` is tracked by git (`git ls-files --error-unmatch <path>`) in `ci.yml` would catch it before a push.
**Lesson:** a reference to an asset must ship in the same commit as the asset. M3 shipped the reference one milestone early.
